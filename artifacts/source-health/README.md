Runtime scope: context-bound source health, report writer, ingestion hooks and existing single/batch results endpoints. No parent routes.ts, provider API, client DTO, source registry, D Dockerfile or shared database changes. Physical npm-ci installation; no dependency junction.

The explicit release-only migration20261013_result_source_health.sql stores electionId+sourceId+state/electionDate/type/level/office, attempt/success observation times, outcome, first staleSince, automatic90s TTL and health transition version. It never runs at boot. Existing source asOf/retrievedAt/status/counts/revision remain immutable when health changes. Manual snapshots retain null/not_provided clocks and get no automatic expiry. TTL expiry is derived deterministically from the durable last success, so restart yields the same staleSince; a recovery beyond that deadline also advances durable cache state.

One bounded health query reads at most one row per race, at most600 requested races. Latest report source controls decoration; when no report exists, admitted current registry/manifest sources qualify health. All five exact authoritative context fields match, so old health does not bleed through an edited race or changed registration. No absent/error branch manufactures freshness. Public stale/staleSince fields already existed. Internal, nonserialized cache metadata includes health transition version, making outage/recovery invalidate single ETags and batch cursors even when the report revision does not change; ordinary healthy polls do not churn that version.

Successful report and its health update commit in the same transaction. Identical fresh capture compares normalized COMPLETE published content against actual stored rows/lines, ignoring capture time, note and input ordering only. Original input_sha256/revision are unchanged. Source/reporting/status/option identities/counts/certification/winner provenance remain comparison inputs; current full context bounds the SQL. Same raw workbook SHA with changed WA recount votes remains a new report. Replaying an older, already-recorded report preserves current counts and idempotence but cannot renew health on the newer revision. Abort signals reach transactional writer and health writes; stopped and late adapters perform no report/health writes, and an abort after actual SQL insert rolls back without later mutation calls.
